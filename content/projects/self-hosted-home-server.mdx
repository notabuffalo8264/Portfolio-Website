### How This Started

This started because I wanted a real server to experiment with instead of running everything on my main desktop.

I bought a refurbished **Lenovo ThinkCentre M720 SFF** for around $200 and turned it into a headless Ubuntu server. At first, the goal was mostly game hosting, but it quickly became a broader home lab for Docker apps, automation, local AI, dashboards, remote access, DNS filtering, file sharing, and media storage.

## What It Runs

The server is a mix of Docker containers, native Linux services, and a few tools running directly on Ubuntu.

Main services include:

- **Glance** for my custom startpage and server dashboard
- **Portainer** for Docker management
- **n8n** for self-hosted automations
- **Ollama + Qwen** for local AI workflows
- **Jellyfin** for my media library
- **Pi-hole** for network-wide DNS filtering
- **FileBrowser Quantum** for temporary public file sharing
- **Samba** for private file access over Tailscale
- **CubeCoders AMP** for lightweight game-server management
- **Tailscale** for private remote access

The server also has an **8 TB external media drive** for Jellyfin and a separate internal HDD setup for personal storage, backups, and capped public sharing.

## Custom Dashboard

One of the most useful parts of the project is the **Glance** dashboard.

I built a dedicated Home Server page so I could see the things I actually care about in one place: system stats, storage, network status, security status, Docker services, Jellyfin activity, Pi-hole DNS stats, AI/n8n status, and useful management links.

I also built small Python helper services that expose custom server data to Glance. These pull from tools like AMP, Pi-hole, Jellyfin, FileBrowser, and system services so the dashboard feels more like a real control panel than a basic bookmark page.

## Automation and Local AI

I self-host **n8n** so I can build automations that run on my own server instead of relying only on cloud workflow tools.

I also installed **Ollama** with a small Qwen model so some workflows can use local AI. Since the server is CPU-only, I kept the setup realistic: smaller model, careful prompt sizes, and workflows that do not need a ton of parallel requests.

One workflow I built around this is an AI-assisted email categorizer. It pulls messages from Fastmail through JMAP, sends the useful parts to the local model, and applies labels without giving the automation permission to delete, archive, or send mail.

## Storage, Media, and File Sharing

I set up **Jellyfin** with an attached **8 TB external drive** for media storage.

I use it to organize and stream a personal media library made from physical disks, along with home videos and home photos. The server uses Intel Quick Sync hardware transcoding, so playback and conversion work is handled by the i7-9700's integrated graphics instead of relying only on the CPU.

I also configured the internal HDD for private and shared storage. Personal files and backups are available through **Samba** over Tailscale, while **FileBrowser Quantum** is used for temporary public sharing through a **Cloudflare Tunnel** at my own domain. The public shared folder is hard-capped so uploads cannot fill the entire drive.

## Remote Access and Security

I wanted the server to be useful remotely, but I did not want every admin page exposed to the public internet.

Most management happens through **SSH**, **VS Code Remote SSH**, and **Tailscale**. Admin tools like Portainer, Glance, n8n, Jellyfin, AMP, Samba, and Pi-hole stay private on my LAN or Tailscale network.

The only things intended for public access are specific services that need it, like temporary FileBrowser shares through Cloudflare Tunnel or a game-server port when needed. This part of the project taught me a lot about firewall rules, ports, Docker networking, host-to-container communication, DNS, and deciding what should actually be public.

## Why I Like This Project

The best part of this project is that it keeps growing.

It started as a cheap refurbished desktop, but now it acts like a small personal infrastructure platform. I can host apps, test automations, run local AI workflows, manage media, share files, filter DNS, experiment with networking, and keep adding new services as I think of them.

It has been one of the most useful projects I have built because it is not just something I finished once. It is something I actually use and keep improving.
